# Design Document: aws-deployment

## Overview

The weather app is deployed as a static site: a private S3 bucket holds `index.html`, `styles.css`, and `weather.js`, and CloudFront serves them over HTTPS. CloudFront is the only reader of the bucket, through Origin Access Control (OAC). A CloudFront response headers policy adds the security headers. One CloudFormation template defines all of it.

A Jupyter notebook runs the deployment one step at a time, with a markdown explanation before each step. It follows the same conventions as the `container-demo` notebooks (`2048-demo.ipynb` and the others): `!aws` lines, values read with `--query ... --output text`, cells that are safe to re-run, and a final cell that clears saved outputs.

**Prerequisite:** `styles.css` exists and `index.html` has no `<style>` block (see requirements). The notebook checks this before deploying.

---

## Architecture

```text
Browser
  │  HTTPS (HTTP is redirected)
  ▼
CloudFront distribution ── response headers policy (CSP, HSTS, nosniff, frame deny, referrer)
  │  signed requests (OAC, SigV4)
  ▼
S3 bucket (private) ── Block Public Access, SSE-S3, versioning, bucket owner enforced
      index.html, styles.css, weather.js

Browser ──HTTPS──> nominatim.openstreetmap.org   (unchanged)
Browser ──HTTPS──> api.weather.gov               (unchanged)
```

The stack is created in the profile's default region. CloudFront itself is a global service, but the stack, the bucket, and the CloudFormation console view all live in that region.

## CloudFormation Template (`infra/weather-app.yaml`)

No parameters. Names that must be unique are either generated by CloudFormation (bucket) or derived from `AWS::StackName` (OAC and headers policy names, which must be unique per account).

### Resources

| Logical ID | Type | Key settings | Req |
|---|---|---|---|
| `SiteBucket` | `AWS::S3::Bucket` | No `BucketName` (CloudFormation generates one). `PublicAccessBlockConfiguration` with all four settings `true`. `BucketEncryption` with `SSEAlgorithm: AES256`. `VersioningConfiguration: Enabled`. `OwnershipControls: BucketOwnerEnforced` (ACLs off). No `WebsiteConfiguration`. Tag `Project=weather-app`. | 1.2, 1.4, 2.1, 2.2, 2.4, 2.5 |
| `SiteOAC` | `AWS::CloudFront::OriginAccessControl` | `Name: !Sub ${AWS::StackName}-oac`, origin type `s3`, `SigningBehavior: always`, `SigningProtocol: sigv4`. | 3.1 |
| `SecurityHeadersPolicy` | `AWS::CloudFront::ResponseHeadersPolicy` | `Name: !Sub ${AWS::StackName}-security-headers`. Security headers listed below, each with `Override: true`. | 4.1, 4.2 |
| `Distribution` | `AWS::CloudFront::Distribution` | See below. Tag `Project=weather-app`. | 3.1–3.4 |
| `SiteBucketPolicy` | `AWS::S3::BucketPolicy` | Statement 1: allow `s3:GetObject` on `${SiteBucket.Arn}/*` to principal `Service: cloudfront.amazonaws.com` with condition `StringEquals AWS:SourceArn arn:${AWS::Partition}:cloudfront::${AWS::AccountId}:distribution/${Distribution}`. Statement 2: deny `s3:*` when `aws:SecureTransport` is `false`. | 2.3, 2.6 |

OAC and response headers policies do not support tags in CloudFormation, so only the bucket and distribution carry the `Project` tag. The notebook also passes `--tags Project=weather-app` to `cloudformation deploy`, which tags the stack and propagates to taggable resources.

`${AWS::AccountId}` and `${AWS::Partition}` are pseudo parameters resolved at deploy time, so nothing account-specific is written in the template (Req 1.2).

### Distribution settings

| Setting | Value | Why |
|---|---|---|
| `Origins[0].DomainName` | `!GetAtt SiteBucket.RegionalDomainName` | Regional REST endpoint, required for OAC. Not the website endpoint. |
| `Origins[0].S3OriginConfig.OriginAccessIdentity` | `""` | Required empty value when using OAC instead of the legacy OAI. |
| `Origins[0].OriginAccessControlId` | `!GetAtt SiteOAC.Id` | Signs origin requests so the bucket policy can admit them. |
| `DefaultRootObject` | `index.html` | `/` serves the app (Req 3.3). |
| `DefaultCacheBehavior.ViewerProtocolPolicy` | `redirect-to-https` | Req 3.2. |
| `DefaultCacheBehavior.AllowedMethods` | `GET`, `HEAD` | Read-only site. |
| `DefaultCacheBehavior.Compress` | `true` | Req 3.4. |
| `DefaultCacheBehavior.CachePolicyId` | `658327ea-f89d-4fab-a63d-7e88639e58f6` (managed `CachingOptimized`) | AWS-managed policy; honors the origin's `s-maxage`. |
| `DefaultCacheBehavior.ResponseHeadersPolicyId` | `!Ref SecurityHeadersPolicy` | Req 4. |
| `HttpVersion` | `http2and3` | Current protocol defaults. |
| `PriceClass` | `PriceClass_100` | Lowest-cost edge locations (North America, Europe); fits a U.S.-only app. |
| `ViewerCertificate.CloudFrontDefaultCertificate` | `true` | `*.cloudfront.net` certificate; no custom domain in scope. |

### Security headers

| Header | Value |
|---|---|
| `Content-Security-Policy` | `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self' https://nominatim.openstreetmap.org https://api.weather.gov; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` |
| `Strict-Transport-Security` | `max-age=31536000` (no `includeSubDomains` or `preload`; the site uses a shared `cloudfront.net` name) |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |

`default-src 'none'` blocks anything not listed. `img-src 'self'` covers the browser's automatic `/favicon.ico` request. Weather icons are emoji text, not images. No directive includes `'unsafe-inline'` (Req 4.2).

### Outputs

| Output key | Value | Used by |
|---|---|---|
| `BucketName` | `!Ref SiteBucket` | Upload and cleanup cells |
| `BucketRegionalDomainName` | `!GetAtt SiteBucket.RegionalDomainName` | Direct-S3 "denied" check |
| `DistributionId` | `!Ref Distribution` | Invalidation cell |
| `DistributionDomainName` | `!GetAtt Distribution.DomainName` | HTTP redirect check |
| `SiteURL` | `!Sub https://${Distribution.DomainName}` | Printed for the user (Req 1.3) |

## Caching

The filenames do not change between releases, so the design uses two different cache lifetimes:

| Cache | Header on each uploaded object | Effect |
|---|---|---|
| Browser | `max-age=0` | The browser revalidates on every load (gets a quick `304 Not Modified` when nothing changed). Req 5.5. |
| CloudFront edge | `s-maxage=86400` | Edges keep the file for up to one day, so most requests never reach S3. |

The full header is `Cache-Control: max-age=0, s-maxage=86400`. Because edges hold files for a day, every deploy ends with an invalidation of `/*` so the new files are served right away (Req 5.6). One `/*` path counts as a single invalidation path; AWS does not charge for the first 1,000 paths each month.

This caching applies only to the app's static files. Weather data is still fetched live from the NWS on every lookup, as the project steering requires.

## Notebook (`deploy-aws.ipynb`)

Python 3 kernel. Each part starts with a markdown cell that explains what the step does and why, and defines new terms. Code cells use `!aws`, `!curl`, and `!type`. Python is limited to variables, `if`, `for`, and `subprocess.run(...).returncode` existence checks, as in `container-demo`.

### Conventions

- Values are read with `out = !aws ... --query ... --output text` then `x = out.s.strip()`. A missing value comes back as the text `None`.
- JMESPath queries use double quotes outside and single quotes inside (`"Stacks[0].Outputs[?OutputKey=='BucketName'].OutputValue"`), which works in Windows cmd. No `{...}` appears in `!` lines except intended Python variables.
- Stack outputs are re-read at the top of each part (upload, verify, cleanup), so a part still works after a kernel restart.
- No profile, region, or account ID appears anywhere (Req 5.2).

### Cell plan

| # | Part | Cells | Req |
|---|---|---|---|
| 0 | Intro | Title, architecture diagram, "start Jupyter from the repo folder in a terminal where you ran `aws sso login` and set `AWS_PROFILE`". Lists the resources that will be created. | 5.1 |
| 1 | Who am I | `!aws sts get-caller-identity`. Explains account, role ARN, and that the profile also sets the region. | 5.2 |
| 2 | Settings and prerequisite | `STACK = "weather-app"`, `TEMPLATE = "infra/weather-app.yaml"`. Checks that `styles.css` exists and `index.html` has no `<style`; prints a clear message and stops if not. | Prereq |
| 3 | Read the template | `!type infra\weather-app.yaml` with markdown walking through each resource. | 5.1 |
| 4 | Validate | `!aws cloudformation validate-template --template-body file://infra/weather-app.yaml --query Description --output text` | 1.5, 5.4 |
| 5 | Create or update the stack | Warning cell: first run takes about 5 minutes and is mostly silent while CloudFront is created. Then `!aws cloudformation deploy --stack-name {STACK} --template-file {TEMPLATE} --tags Project=weather-app --no-fail-on-empty-changeset`. `deploy` creates the stack if missing, updates it if changed, and with `--no-fail-on-empty-changeset` exits cleanly when nothing changed. | 5.4, 5.9, 5.10 |
| 6 | Read outputs | Four `describe-stacks` queries into `BUCKET`, `DIST_ID`, `DIST_DOMAIN`, `BUCKET_DOMAIN`; `SITE_URL = "https://" + DIST_DOMAIN`. | 1.3 |
| 7 | Upload | Three `!aws s3 cp` lines, one per App_File, each with `--content-type` (`text/html; charset=utf-8`, `text/css; charset=utf-8`, `application/javascript; charset=utf-8`) and `--cache-control "max-age=0, s-maxage=86400"`. One line per file keeps it explicit that nothing else is uploaded. | 5.5 |
| 8 | Invalidate | `out = !aws cloudfront create-invalidation --distribution-id {DIST_ID} --paths "/*" --query Invalidation.Id --output text`, then `!aws cloudfront wait invalidation-completed --distribution-id {DIST_ID} --id {INV_ID}`. Warning: the wait often takes 1–2 minutes. | 5.6, 5.10 |
| 9 | Verify | Print `SITE_URL`. `!curl -sI {SITE_URL}` (expect `200` and the five security headers). `!curl -sI http://{DIST_DOMAIN}/` (expect `301` to HTTPS). `!curl -sI https://{BUCKET_DOMAIN}/index.html` (expect `403`). Markdown explains each result. | 2.6, 3.2, 5.7 |
| 10 | Browser test | Open `SITE_URL`, look up a city, open DevTools > Console and confirm there are no CSP errors. A `403` for `favicon.ico` is expected and harmless. | 3.5, 4.3 |
| 11 | Console tour | `!aws cloudformation describe-stack-resources --stack-name {STACK} --query "StackResources[].[LogicalResourceId,ResourceType,ResourceStatus]" --output table`, then a markdown table of where to look: CloudFormation > Stacks > weather-app (Resources, Outputs); S3 > Buckets > bucket (Objects, Permissions: Block Public Access and bucket policy, Properties: Versioning and encryption); CloudFront > Distributions > distribution (Origins: OAC, Behaviors, Invalidations); CloudFront > Policies > Response headers. | 5.8 |
| 12 | Cleanup: empty bucket | Checks the stack exists with `subprocess.run(f"aws cloudformation describe-stacks --stack-name {STACK}", shell=True, capture_output=True).returncode`; if not, prints "nothing to delete". Otherwise reads `BUCKET`, lists `Versions[].[Key,VersionId]` and `DeleteMarkers[].[Key,VersionId]` with `--output text`, and for each line runs `aws s3api delete-object --bucket ... --key ... --version-id ...`. Markdown explains why a versioned bucket must be emptied version by version before CloudFormation can delete it. | 6.1, 6.2 |
| 13 | Cleanup: delete stack | Same existence check. Warning: deletion takes about 5–15 minutes because CloudFront disables the distribution first. `!aws cloudformation delete-stack ...` then `!aws cloudformation wait stack-delete-complete ...`, then prints the final status. | 6.1, 6.2 |
| 14 | Clear outputs | Same cell as `container-demo`: load the `.ipynb` with `json`, empty `outputs` and `execution_count` for code cells, write it back, then tell the user to close without saving and reopen. Writing the notebook file is one of the allowed uses of `json`. | 6.3 |

### Re-run behavior (Req 5.9)

| Cell | Second run |
|---|---|
| Validate, read outputs, verify, tour | Read-only. |
| Deploy | No changes, so `--no-fail-on-empty-changeset` exits 0. |
| Upload | Overwrites the same keys and adds a new S3 version. |
| Invalidate | Creates another invalidation, which is still free. |
| Cleanup | The existence check reports nothing to delete. |

**Known non-re-runnable state:** if the first stack creation fails, CloudFormation leaves the stack in `ROLLBACK_COMPLETE`, and `deploy` cannot update it. The deploy markdown tells the reader to run the cleanup cells and then deploy again.

## Error Handling

| Situation | Behavior |
|---|---|
| Not signed in or token expired | `sts get-caller-identity` fails visibly in cell 1; the markdown tells the reader to run `aws sso login` and restart Jupyter from that terminal. |
| `styles.css` missing or inline `<style>` present | Cell 2 prints what is missing and does not continue. |
| Template invalid | Cell 4 prints the CloudFormation error. |
| Stack create failed (`ROLLBACK_COMPLETE`) | Run the cleanup cells, then cell 5 again. |
| Stack does not exist during cleanup | Cleanup cells print "nothing to delete". |

## Testing Strategy

Following the project steering, no test framework is added. Verification is:

1. `aws cloudformation validate-template` passes (cell 4).
2. The `curl` checks in cell 9 show `200` with the security headers from CloudFront, `301` from HTTP, and `403` from S3 directly.
3. The manual browser test in cell 10 shows the forecast with styling and no CSP errors in the console.
4. Running every deploy cell a second time produces no errors.
5. Cleanup removes the stack; `describe-stacks` then reports that the stack does not exist.
6. After the clear-outputs cell, the saved notebook has empty outputs. Before committing, staged files are searched for 12-digit numbers and the user's email.

The user runs the notebook against their own account. The implementer validates the template and checks the notebook structure, but does not deploy unless the user asks.
